# 静态障碍物人工势场避障

## 场景参数

固件和 PyBullet 场景共享同一个长方体障碍物：

| 参数 | 值 |
|---|---:|
| minimum | `(-0.64, -0.46, 0.30) m` |
| maximum | `(-0.58, -0.40, 0.60) m` |
| clearance | `0.04 m` |
| influence radius | `0.20 m` |
| repulsive gain | `0.02` |

起点关节为 `(0.30, -1.0, 1.0, -1.0, 0.8, 0.2)`，终点关节为
`(0.50, -1.0, 1.0, -1.0, 0.8, 0.2)`。脚本通过正运动学生成起点和终点位姿，再发送
`CARTESIAN_LINE` 命令。

## C 实现

`firmware/app/artificial_potential_field.c` 使用固定大小的 AABB 障碍物数组，不进行堆分配。
每个控制周期根据末端当前位置和笛卡尔名义目标计算：

- 吸引力：将末端拉向直线或圆弧的当前目标点；
- 斥力：对影响半径内的障碍物施加远离最近点的力；
- 安全余量：将 AABB 外扩 `clearance_m` 后参与距离计算；
- 步长限制：限制每周期笛卡尔目标修正量。
- 吸引项不超过到名义目标的剩余距离——吸引增益大于 1，若不加限制，修正量会越过名义
  目标、下一周期再被拉回；限制后，障碍物位于影响半径之外时目标当周期即精确落在名义
  目标上；
- 偏移量（修正后目标与名义目标之差）的每周期变化不超过名义目标的推进量加一个余量
  ——否则目标会以 `step_limit_m` 的幅度跳过平衡点并来回振荡。

`robot_cartesian_update()` 先生成直线/圆弧名义位姿，再执行 APF 位置修正，姿态保持原
SLERP 结果，最后调用 IK 和解筛选。没有配置障碍物时，输出与原笛卡尔轨迹完全一致。
APF 计算运行在 PID 任务上下文，不运行在 UART 或 SysTick ISR 中。

## 由主机下发障碍物

上表的障碍物是固件内置的示例。为了让固件避让的物体与仿真环境渲染的物体完全一致，
`SET_OBSTACLES`（`0x07`）允许主机下发一组 AABB 障碍物（含 `clearance`、`influence`、
`gain`），最多 `ROBOT_APF_MAX_OBSTACLES` 个。路径任务优先使用这组障碍物；`count = 0`
表示清空并回到内置示例。AABB 坐标按 DH 系给出，主机若要在 PyBullet 中建出同一个物体，
需要先转到世界系（两系相差 `diag(-1, -1, 1)`）。

`clearance` 与 `influence` 按场景单独给定：作业点离障碍物越近，影响半径就必须越小，否则
斥力在作业点上不会消失、目标无法收敛。搬运任务场景中 S1～S3 用 `0.03 m / 0.20 m`，
S4（两个障碍物分别离作业点 0.296 m 和 0.286 m）改用 `0.02 m / 0.15 m`。

## 适用边界：长期准静态保持

需要"轨迹结束后继续伺服保持"的行为时必须注意：目标修正是增量式的，斥力项的量纲是
每周期修正米数，在影响半径内可达数米，远大于到名义目标的剩余距离；被 `step_limit_m`
夹住后，每个周期都会推满步长，使修正后的目标被持续推离名义点。

因此该 APF 适用于**运动中的轨迹跟踪**：轨迹持续推进时，名义目标不断前进，吸引力把末端
带回参考路径，偏移量保持在合理范围。它不适用于长时间准静态保持——把整定窗口从 30 个
控制周期放大到 150 个后，即使某一段与障碍物毫无交互，末端也会漂离目标约 0.4 m，且
固件仍上报 `state=RUNNING`、`error=0`。任务级脚本因此保持较小的整定窗口，并用与
抓取/放置相匹配的容差判定。

## PyBullet 验证

运行无头场景：

```bash
cmake --build firmware/build
python3 simulation/scripts/pybullet_apf_scene.py --headless
```

打开可视化场景：

```bash
python3 simulation/scripts/pybullet_apf_scene.py
```

脚本加载 UR5、平面和橙色长方体，绿色/蓝色球分别表示起点/终点；通过 QEMU 发送起始关节
命令和笛卡尔直线命令，周期读取 STATUS，同步 PyBullet 关节状态，并使用
`getClosestPoints()` 检查机器人和障碍物的接触。只有全过程无碰撞且固件状态没有错误时才报告
`PASS`。
